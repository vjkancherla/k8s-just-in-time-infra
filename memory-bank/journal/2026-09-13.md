# 2026-09-13 — Nothing sensitive ever reached GitHub; the checkpoint refs are the landmine

Asked after `.gitignore` was widened: did earlier pushes carry files the new rules now exclude? Checked
against the remote's own refs rather than local history, because the two disagree in this repository.

## Verdict

No. GitHub carries only `refs/heads/main` at `2831f1c`, and neither that tree nor anything reachable from
it has ever contained a `.env`, `terraform.tfstate`, `__pycache__`, `.venv`, `node_modules`, `.DS_Store`,
`.omo/`, `.workflow/`, `README-BAK.md` or a private key.

## What the remote actually holds

- `git ls-remote origin` → exactly two refs, `HEAD` and `refs/heads/main`, both `2831f1c`. No tags, no
  `refs/pull/*`.
- `2831f1c` is the merge-base with local `main`, so `origin/main` was in sync; local `main` is 5 commits
  ahead and unpushed.
- Tip tree, `git ls-tree -r --name-only 2831f1c` filtered for
  `\.env|tfstate|__pycache__|\.pyc$|\.venv|node_modules|\.DS_Store|\.omo|\.workflow|\.bak$|BAK\.md|\.pem$|\.key$|\.tfvars`
  → no output. Same filter over `git log 2831f1c --diff-filter=A --name-only` → no output.
- Every path ever added in the pushed history: 153, being 43 `.md`, 36 `.sh`, 26 `.log`, 14 `.yaml`, 9 `.tf`,
  7 `.py`, 6 `.txt`, 2 `.html`, 2 `.gitignore`, 6 `Dockerfile`s and 2 `Makefile`s. Nothing unexpected.
- The 26 pushed `.log` files are all under `docs/evidence/` — deliberate evidence, and the reason a global
  `*.log` rule is banned in `.gitignore`.
- `.git` is 7.8 MB over 436 commits, so a 38 MB `.venv` could not be hiding in the object database.

## The false alarm — `--all` is not "what I pushed"

`git log --all` reads 119 `refs/cline/checkpoints/*` refs (36 checkpoint groups). Their commits are titled
*"untracked files on cline checkpoint"* and snapshot the entire working tree, `jit-runner/.env`,
`terraform.tfstate`, `.omo/run-continuation/*.json`, `.workflow/verify-jit.md`, `README-BAK.md`,
`app/.workflow/*` and `__pycache__/*.pyc` included. That list is what made the first pass look like a leak.
They are local-only, proven three ways:

- `git merge-base --is-ancestor 1cc3e9b 2831f1c` → exit 1, not an ancestor.
- `git for-each-ref --contains 1cc3e9b` → `refs/cline/checkpoints/1789259345303_8289i`, nothing else.
- Refs by namespace: 119 `refs/cline/`, 1 `refs/heads/` (main), 1 `refs/remotes/` (origin/main).

## Consequence

`git push origin main` cannot publish those objects. `git push --all`, `git push --mirror`, or a GUI "push
all branches and tags" would. `jit-runner/.env` holds one variable, `JIT_RUNNER_TOKEN` (20 characters), and
has never left this machine — no rotation needed unless a mirror push ever happens.

## Re-run before any push

```
git log --branches --remotes --diff-filter=A --name-only | grep -Ei '\.env|tfstate|__pycache__'
```

Empty is the pass (exit 1); verified today. Note the trap this entry exists to record: `git log --all`
includes tooling refs, so it cannot answer "what is published" — `--branches --remotes` can.

`.gitignore`, the make targets and evidence, the plan, README plus the guides, `console/`, the S17 findings,

`app/opencode.jsonc` was held back and ignored instead. It carries a commented `apiKey` for DeepSeek

## The missing console/state.py — found, measured, left as a reference

Reported missing after that push. It was not lost by accident: the S18 session deleted it deliberately
(`README-BAK.md` calls it "the earlier standalone read model; /state now runs `make state`"), and it had never
been committed, so it was never in the published repository. It survived in the local checkpoint snapshots.

Recovery, three commands:

```
git rev-list --all --objects | grep console/state.py    # c1602802 (8035 B, Sep 13), 25f6f05 (6000 B, Sep 12)
git show 16cd174:console/state.py > console/state.py    # newest, byte-for-byte: hash-object matches c1602802
```

The trap worth keeping: `git log --all -- <path>` returned nothing for that path, and `--diff-filter=A`
listed only the three files present in `main`. The checkpoint commits are stash-style merges ("untracked
files on cline checkpoint"), and pathspec history simplification skips changes that merges introduce.
`rev-list --objects` sees them; `git log -- <path>` does not. Two earlier searches in this session were
misled the same way, and both times by content that turned out to be checkpoint-only.

Measured against the live cluster, the recovered file is the *older* read model, not a backup of the current
one — so it was not wired back in:

| field | `make state` (scripts/state.sh) | `console/state.py` |
|---|---|---|
| containers | 3 module containers | 7 — adds `jit-runner` and three `k3d-voting-app-*` |
| stateObjects | 21 | 0 — its MinIO read finds nothing |
| `expiresAt` | `null` | `""` for pgadmin/postgres — the raw spelling the CLI normalises |
| `ingresses` / `ingressPorts` | absent | 2 ingresses, `{http: 8081, https: 8082}` |

The last row is the finding that matters: the page reads those two fields (`console/index.html:670-671`), and
`scripts/state.sh` never emits them, so the Voting-app panes have no URLs to build — the failure
`console/README.md` warns about. The gap is in `make state`, not in the deleted file. On the human's
instruction the recovered file stays on disk untracked as a reference, and `/state` still runs `make state`.

## Silent deletions: what removed files, when, and what else went with them

Prompted by the recovery above: "why was it deleted, and are others gone too?" Answer assembled from the
only witness that exists — the local checkpoint snapshots — because nothing was ever committed.

### Why console/state.py was deleted

The design decision is recorded; the act is not. S18's stated goal (`docs/build-plan.md` S18, and the body of
commit `5a1b59c`) is *"the console's read model comes from `make state` — so the page cannot drift from the
CLI, and nothing in the console shells out to `kubectl` on its own"*. `scripts/state.sh` carries the same
sentence in its header. `README-BAK.md:276` then labels the file *"the earlier standalone read model; /state
now runs `make state`"*, and the previous session's memory bank recorded it as *"deleted (it was dead)"*.

The measurement backs that up: the recovered file is a second, independent read model that shells out to
`kubectl` and `docker` itself, and it had gone stale (7 vs 3 containers, 0 vs 21 state objects, `expiresAt:
""` vs `null`). So the deletion was deliberate and defensible — but it was never committed, never journalled,
and never mentioned in a changelog, because the file was never tracked.

### When, and what else went with it

Each Cline checkpoint writes two commits at one timestamp: a tracked-state commit (which the ref tip points
at) and an "untracked files on cline checkpoint" companion. Comparing the untracked companions brackets the
sweep:

| untracked snapshot | console/state.py | README copy.md | terraform.tfstate |
|---|---|---|---|
| `16cd174` 2026-09-13 01:23:07 | present | present | present |
| `1cc3e9b` 2026-09-13 01:29:54 | **gone** | **gone** | present |

So a clean-up between 01:23 and 01:30 on 2026-09-13 removed `console/state.py` **and** `README copy.md`. The
second was harmless — byte-identical to `README-BAK.md` (both hash `6458aea7`, 22229 bytes). `terraform.tfstate`
still existed at 01:29:54 and is gone now; that happened later, and no command in this session deleted it.

### Everything else that is gone (full audit)

Scanned every commit reachable from any ref plus the 76 unreachable ones (531 commits, 223 distinct paths),
then subtracted HEAD and the working tree. Only 13 paths are gone, and that is the complete list:

| path | verdict |
|---|---|
| `console/state.py` | real source, deliberately superseded — recovered |
| `console/generate.py` | real source (1445 B, 51 lines), last seen 2026-09-12 21:46 — **still missing** |
| `README copy.md` | junk duplicate of `README-BAK.md` |
| `app/kustomize/{ingress,postgres-*,redis-*,result-*,vote-*,worker-*}.yaml` (10) | not deletions — relocated to `app/kustomize/base/` |
| `terraform.tfstate` | 151 B, ignored now; gone from disk after 01:29:54 |

`console/generate.py` wrote a static snapshot: it read `console/template.html`, replaced the
`<script id="state">` element with `console/state.py`'s output, and wrote `docs/console.html`. Neither
`console/template.html` nor `docs/console.html` appears in any object, so the pair may never have existed;
nothing in the repo references the generator, so it was already orphaned when it went.

Recovery, for as long as the checkpoint refs exist (they keep the objects reachable, so `git gc` is safe):

```
git show 7232782:console/generate.py   > console/generate.py
git show 16cd174:'README copy.md'      > 'README copy.md'
git show 1cc3e9b:terraform.tfstate     > terraform.tfstate
```

### The systemic finding

`git log --all --diff-filter=D` returns **nothing** for this repository: no commit has ever deleted a file.
Every disappearance here happened in the working tree, on an untracked file, which leaves no record anywhere
except a local checkpoint snapshot. Two limits are worth knowing: a file created and deleted between two
snapshots leaves no trace at all, and the untracked companions capture only files that were untracked *and
not ignored* at snapshot time. The practical rule: a local extra is either committed, or ignored **and** noted
in the memory bank — an untracked, unignored file can vanish without evidence.
