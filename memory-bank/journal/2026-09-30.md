## The ponytail turn

The human asked whether the work was even required. A ponytail audit of the diff named four
deferrable additions - the startup sweep (a native `docker run --tmpfs /tmp` would do), the
`_CONDITION_TYPES` guard, the module-qualified regex, and arguably create validation - and
the net verdict was that a lazy pass was ~40 lines, not the ~200 that landed. Not backed
out; the lesson is that the audit should run before building, not after.

  The old decks showed bare `'{}'` annotations, "first writer wins", and a wrong postgres
  `referencedBy`.
- References repointed to `-v2` in both READMEs and `docs/designs/console-demo-test-plan.md`
  (which also had a missing `visual-walkthroughs/` path segment) (`1cd57b2`).

## PoC reset

Brought the demo up (`make demo-up`, 17 PASS), smoke-tested it (vote 200, `POST /vote` 302,
tally `Cats 3 Dogs 2`), then `make destroy`. No cluster, runner, MinIO or `voting-*`
containers remain.

## Learnings

- The code fixes were trivial; the repo's verification apparatus was the cost. A ~20-item
  list does not fit an hour under per-step rebuild + live checkpoint + independent review.
- A documentation model change is part of the change: the S22 declarer/consumer rewrite
  reached the design notes but not the README, demo doc, or walkthroughs.
- For visual artefacts the `-v2` convention (keep the original, add a corrected copy,
  repoint references) is cheaper than in-place churn and keeps the v1 decks usable.
