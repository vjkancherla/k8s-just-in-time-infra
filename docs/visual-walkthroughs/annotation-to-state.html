One annotation line, five artefacts later.

A tenant writes jit.infra/redis on a Deployment. What comes out the other end is an InfraClaim, an IP, a Docker container, three Kubernetes objects and a Terraform state file in MinIO. This page resolves that chain for a namespace and a module you pick — and it is the chain to walk when something has gone wrong.

The chain in one line

    
Nine hops, and only the last one is visible to the application.

    

      
annotation
jit.infra/<module>

      →
      
parse_annotations()
the module name

      →
      
InfraClaim
{ns}-{module}

      →
      
IPAM
one address

      →
      
POST /v1/runs
module + workspace + params

      →
      
tofu apply
the container is created

      →
      
MinIO
the state file

      →
      
outputs
address, port, url

      →
      
Secret, Service, EndpointSlice
the pod starts

    

    
Everything from hop 2 to hop 8 is invisible to the tenant. The Deployment names a
    Secret; the pod cannot start until that Secret exists; none of the machinery in between is its
    business.

  






  

    
The naming rule, applied

    
Every layer is the same two words in a different arrangement. The example column follows
    the picker above.

    

      
LayerPatternFor this selection

      
        
Annotation keyjit.infra/{module}

        
InfraClaim{namespace}-{module}

        
Container{namespace}-{module}-{module}

        
Secretjit-{module}

        
Servicejit-{module}

        
MinIO keyns/{namespace}/{module}/terraform.tfstate

        
IPAM block10 addresses per namespace

      
    

    
The container name looks redundant — redis-redis —
    because the module's Terraform appends the module name to whatever name variable it is given,
    and the controller sets that variable to {namespace}-{module}.
