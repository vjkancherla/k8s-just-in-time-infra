What each part of this does.

    
The console runs make targets and shows what the cluster says. It stores nothing of its own, so anything here that looks wrong is the stack, not the page.


    
The two modes

    

      

        
Demo
          One namespace, voting-a, and four steps in order. Fewer containers and faster to start. Use it to show someone what the design does.

        
Testing
          Both namespaces and the check suites. voting-b exists so the hard-delete check can prove one namespace going away leaves the other alone.

      

      
Switching mode changes which actions are listed. It does not change the cluster.

    


    
The tabs

    

      

        
Setup
          Runs things. Each row is one make target; output streams into the log underneath and is also written to docs/evidence/.

        
Infrastructure
          What exists right now, grouped by namespace. Each claim maps to a container running outside the cluster. The feed at the bottom shows phase changes observed while this page has been open.

        
Voting app
          The vote and result pages embedded, for whichever namespace is selected. Hosts and ports come from the cluster's Ingress objects, not from anything typed here.

        
Guide
          This page. What each tab, mode, claim state and button does.

      

    


    
What a claim's state means

    

      

      
The countdown is worked out in the browser from the expiry the controller wrote. The console never decides when something expires.

    


    
Every action, and what it runs

    

      

      
These come from the page's own list, so this table cannot drift from the buttons. The names must also appear in make targets or the run is refused.

    


    
Things that will confuse you otherwise

    

      

        
The app panes are blank.
          HTTPS with a self-signed certificate. Use Open once per host, accept the warning, reload. The browser gives the page no way to detect this.

        
The log is empty after a restart.
          The output is still in docs/evidence/. The page only reads a log while its run is in progress.

        
Ctrl-C during a run.
          Stops the server, not the make it started. Check docker ps and k3d cluster list before starting again.

        
Nothing appears at all.
          Run make -s state in a terminal. If that prints nothing useful, the console is reporting it correctly.

      

    


    
Where the numbers come from

    

      
Claims, phases, addresses, expiry, containers, state objects and Ingress hosts all arrive from one call to make state, polled every two seconds. That reads the same sources the frozen checkpoints read, which is what keeps this page and make jit-verify from ever disagreeing.
